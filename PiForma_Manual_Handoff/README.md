# Macintosh PiForma Owner's Guide: Codex editorial handoff

This is the content and editorial brief for a new, authentic-feeling late-1980s Macintosh owner's guide. It is **not** a command to copy Apple's text verbatim. The reference manuals establish sequence, typographic vocabulary, illustration conventions, tone and information architecture. PiForma documentation must describe this real, one-off build.

## Recommended reading order for Codex

1. `CODEX_START_HERE.md` for the task and source-of-truth hierarchy.
2. `content/01-annotated-contents.md` for the book's structure.
3. `content/02-chapter-1-getting-started.md` for detailed user-supplied operations and sequence.
4. `content/03-chapters-2-to-4.md` for hardware, software, care and appendixes.
5. `reference/verified-facts-and-uncertainties.md` for confidence levels and conflicts.
6. `content/04-voice-and-sample-prose.md` for writing style and model passages.
7. `plans/illustration-shot-list.md` and `plans/open-questions.md` for needed photos and hardware checks.
8. `plans/production-workflow.md` for drafting and typesetting gates.

## Source precedence

1. New observations, photographs and instructions explicitly supplied by the owner.
2. The owner's active `Macintosh-PiForma-docs` repository and live configuration, **after inspecting them**.
3. This packet's user-dictated narrative and historically confirmed project facts.
4. Existing prototype Typst source and produced PDFs.
5. Original Apple manuals as layout and chapter-order references, **not** as a source for PiForma specifications.

When these conflict, flag the discrepancy rather than silently selecting a fact. Never invent battery capacity, electrical safety certification, USB pinouts, speaker models, keyboard shortcut behaviors, chime module failure causes or serviceability.

## Editorial intent

A real, helpful owner's guide to a playful experimental Macintosh PiForma. Readable by someone who did not build it. The wit is occasional and dry, with the occasional personal aside; the bulk of the writing is clear, welcoming and precise. Avoid marketing copy, filler, invented Apple history, and fake claims of Apple authorization or warranty.

## Scope

Full book outline and drafting resources, not just the earlier four-page typography prototype. There is no need to match the originals' word count, chapter lengths, appendix count, or page count. No SCSI chapter, Apple user groups, 'other manuals' section, 3.5-inch disk care, product-line comparison, or index in the initial release.
